# Compatibility matrix — 1.3.2

2026-09-08。本表区分源码/本地运行验证和目标宿主实际加载，旧 1.2.0 报告不证明新版兼容。

| 宿主/环境 | 安装发现 | 质量门/图像链路 | 写入 | 结论 |
|---|---|---|---|---|
| 当前 Codex 工作区，macOS 26.6 / Python 3.14.7 | 当前项目根 Skill 已读取；未修改用户已安装 Skill | portable 与原生回归通过；Vision/ImageIO 实际运行；JPEG 蓝边被视觉门拒绝 | 临时夹具单目标写入/读回与内容保护通过 | 本地源码已验证 |
| DeepSeek Harness | 官方 `.dsh/skills`、全局 dshHome、目录包已核实 | 共享标准库测试可运行；本客户端未实测 | 未实测 | 结构支持，端到端待验 |
| WorkBuddy | 官方上传技能包界面已核实；无猜测路径 | 共享标准库测试可运行；本客户端未实测 | 未实测 | 结构支持，端到端待验 |
| 无原生能力的宿主 | 按对应宿主发现规则 | 模拟 Linux 无原生工具分支验证 JPEG 拒绝；合格 PNG 仍需真实预览审查 | 不承诺设置 macOS 图标 | 安全降级已验证，非 Linux 实机认证 |

证据在本项目 `.cross-platform-audit/`，发布包不携带本机运行数据。`patch-1.3.2/mvp/mvp-report.json` 与 `patch-1.3.2/install-e2e.json` 记录最新隔离结果。`tests/test_native_gate.py` 检查原生、Python、Terminal 三入口拒绝且目标元数据未变；其余五个测试脚本覆盖 portable、三路由资格检查，以及 MVP 生成器拒绝用户图片。

JPEG 的“提取成功”不是“合格图标”：原有 JPEG 样本因疑似矩形被拒；新增 JPEG 圆形样本技术通过，但实际预览发现蓝色边缘，视觉失败，因此未应用。PNG 正向写入使用确定性合成透明夹具。不得把这些结果扩大为任意图片自动抠图成功。
